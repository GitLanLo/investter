# Техническое задание: Проект "Invest"

## 1. Наименование проекта
**Invest** — веб-система мониторинга и анализа движения цены ценных бумаг с использованием моделей машинного обучения.

## 2. Цель проекта
Разработать веб-приложение, позволяющее пользователям отслеживать выбранные ценные бумаги, загружать рыночные данные через Tinkoff Invest API, анализировать движение цены на графиках, рассчитывать технические индикаторы и получать оценку вероятности торгового сигнала на основе моделей машинного обучения.

## 3. Назначение системы
Система предназначена для частных пользователей, которые хотят:
- отслеживать интересующие ценные бумаги;
- просматривать свечные графики;
- анализировать технические индикаторы;
- учитывать внешние рыночные факторы;
- получать вероятностную оценку сигнала;
- настраивать уведомления;
- вести личный список наблюдения.

*Система не является торговым терминалом и не должна автоматически совершать сделки.*

---

## 4. Основные пользовательские сценарии

### 4.1 Регистрация и вход
1. Регистрация по email и паролю.
2. Вход в систему.
3. Выход из системы.
4. Получение информации о профиле.

### 4.2 Подключение Tinkoff Invest API
1. Настройки профиля: добавление Tinkoff Invest API token.
2. Выбор режима: sandbox или prod.
3. Проверка корректности токена.
4. Удаление токена.
5. Статус подключения.
*Токен хранится в зашифрованном виде.*

### 4.3 Поиск и добавление ценных бумаг
1. Поиск инструмента по тикеру или названию.
2. Просмотр найденных инструментов.
3. Добавление в watchlist.
4. Удаление из watchlist.

### 4.4 Мониторинг watchlist
Таблица избранных бумаг: тикер, название, биржа, цена, изменение, последний сигнал, вероятность, статус свежести данных.

### 4.5 Страница инструмента
Отображение:
- Свечной график (5m, 15m, 1h, 1d).
- Объемы, индикаторы (EMA, RSI, ATR, VWAP).
- Внешние факторы (USD/RUB, Brent, RTSI/IMOEX).
- Текущий ML-сигнал и вероятность.
- История сигналов.
- Кнопки обновления данных и запуска анализа.

### 4.6 Анализ и сигналы
Расчет вероятностей: up / down / no-trade. Отображение версии модели, порога и горизонта.

### 4.7 Уведомления
Правила: порог вероятности, новый сигнал, устаревшие данные. Пока только внутриприложенческие.

### 4.8 Административный ML-раздел
Отдельный раздел для оператора: активная модель, отчеты, validation runs, policy gate, monitoring summary, artifacts.

## 5. Функциональные требования (FR)
- **FR-AUTH**: Регистрация, вход (JWT), bcrypt для паролей.
- **FR-TINKOFF**: Шифрованное хранение токена (AES-GCM), маскирование (hint).
- **FR-INSTR**: Поиск и управление индивидуальным watchlist.
- **FR-MD**: Загрузка/хранение свечей, проверка на дубли/пропуски.
- **FR-IND/FACT**: Расчет EMA, RSI, ATR, VWAP; учет USD/RUB, Brent, Индексов.
- **FR-ML**: Запуск анализа, хранение истории сигналов, статусы моделей.
- **FR-ALERT**: CRUD правил уведомлений, история сработок.
- **FR-ADMIN**: Просмотр метаданных моделей и мониторинга.

## 6. Нефункциональные требования (NFR)
- **NFR-SEC**: Хэширование паролей, шифрование токенов, изоляция данных пользователей.
- **NFR-PERF**: Загрузка watchlist < 2с, график < 3с.
- **NFR-REL**: Обработка ошибок API Тинькофф, отсутствие дублей при загрузке.
- **NFR-DEV**: Docker Compose, Makefile, README.

## 7. Структура API (/api/v1)
- `/auth/register`, `/login`, `/logout`, `/refresh`, `/me`
- `/me/tinkoff-token` (GET/POST/DELETE/TEST)
- `/instruments/search`, `/{id}/summary`
- `/watchlist` (GET/POST/DELETE), `/watchlist/freshness`
- `/assets/{id}/candles`, `/factors`, `/indicators`, `/refresh`
- `/signals/latest`, `/{id}/signals`, `/{id}/analysis/run`
- `/alerts/rules`, `/alerts/events`
- `/admin/ml/...` (models, research, monitoring)

## 8. План разработки

### Этап 1. Подготовка backend
1. Исправить версии Go и Dockerfile.
2. Разбить `router.go` на handlers.
3. Ввести `/api/v1` prefix.
4. Middleware: логирование, обработка ошибок.

### Этап 2. Авторизация
1. Таблица `users`, хэширование.
2. Регистрация/вход/выход (JWT).
3. Тесты Auth.

### Этап 3. Tinkoff token
1. Таблица `user_tinkoff_credentials`.
2. Шифрование AES-GCM.
3. Обновление `TinkoffAdapter` (user-scoped).

### Этап 4. User-scoped watchlist
1. Привязка к `user_id`, обновление repo/service/endpoints.

### Этап 5. Market data и analysis
1. Обновление по токену пользователя.
2. Endpoints: `refresh`, `indicators`, `summary`.

### Этап 6. Frontend
1. Routing, Login/Register pages.
2. SettingsTinkoff, Watchlist, Instrument pages.
3. Перенос старого ML-board в AdminML.

### Этап 7. Уведомления
1. User-scoped rules, UI, история событий.

### Этап 8. Подготовка к защите
1. Документация, README, демонстрационный сценарий.

## 9. План тестирования
- **Unit**: Auth, Tinkoff Creds, Watchlist, Market Data, Signals.
- **Integration**: API endpoints (Auth, Token, WL, MD, Signals, Alerts).
- **Frontend**: Auth UI, Settings, Watchlist, Instrument page, Alerts UI.
- **E2E**: Сценарии "первый вход", "подключение токена", "добавление бумаги", "анализ", "уведомление", "изоляция".
- **Security**: Проверка JWT, изоляции данных, отсутствия plain-text токенов.
- **Data/ML**: Качество свечей, расчет таргетов, инференс модели.
- **Smoke**: Health/ready checks, базовые GET после логина.
